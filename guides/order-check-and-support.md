# 充值订单完成后：怎样验收与申请售后

订单显示“已完成”后，还需要确认交付内容与购买规格一致。建议由自己登录目标账号检查，保存必要记录；不要只依据客服截图判断结果。

## 第一步：找到这笔订单

使用[游客订单查询](https://vipai.pro/guest/orders)或登录后的订单页面，核对订单号、商品、规格、金额和状态，并与付款记录对应。

超过商品说明的处理时间或出现失败提示，先联系站内客服核实，不要连续重复下单。

## 第二步：按商品类型检查

| 所购内容 | 建议检查 | 记录方式 |
| --- | --- | --- |
| 会员开通、升级或续费 | 目标账号、套餐名称、生效状态、页面显示的时间 | 自己打开订阅页面；保留脱敏截图 |
| 点数或活动相关服务 | 到账账户、相关记录、数量、适用范围和有效期 | 对照购前说明记录差异；没有展示的字段标为待确认 |
| API 额度 | 服务商控制台余额、接口与计费账户 | 核对余额变化；如需试用，先确认会否产生费用 |
| 兑换类商品 | 所交付内容、兑换要求与有效期 | 按商品步骤验收；不要公开兑换码 |

表格列的是检查方法，不是对所有商品的统一交付承诺。具体验收标准以所购商品及交易约定为准。

例如：续费后套餐名称可能没变，应比较到期或账单信息；页面信息不足时，请客服说明对应交付结果。

## 第三步：出现差异时，一次说明清楚

先保存当前状态，再通过网站公布的客服入口联系。可使用下面的格式，涉及订单的内容只发送到已确认的私密客服渠道：

> - 订单号：【订单号】
> - 商品及规格：【名称／规格】
> - 付款时间：【时间】
> - 订单当前显示：【状态原文】
> - 商品约定的交付内容：【约定】
> - 我实际看到的结果：【结果或报错原文】
> - 已尝试的步骤：【步骤，没有则填无】
> - 希望核实：【交付进度／规格差异／售后处理】

附图只保留套餐、时间、状态或报错等相关部分。遮住密码、验证码、完整支付信息、登录凭据与 API 密钥。不要将这些信息贴进 GitHub Issue，也不要发到陌生人的私信里。

## 第四步：按约定处理，不自行推断结果

阅读[售后说明](https://vipai.pro/after-sales)及商品条款，确认适用情况、材料和申请方式。客服提出方案时，明确范围与时间并保留记录。

“已反馈”“已受理”“已退款”和“资金实际到账”是不同状态。对方说已处理后，再检查订单或支付渠道中的实际结果。本文不额外承诺退款条件，也不替商品条款作保证。
